## 为什么测试是学习的最佳入口

阅读测试比阅读源码有以下优势：

1. **只关注一个功能点**：每个 `test_xxx()` 只验证一个行为，不需要理解整个系统
2. **展示API的正确用法**：测试代码就是"最佳实践示例"
3. **即改即验**：修改代码后跑测试，马上知道对不对

## 测试框架

项目用最简单的自定义测试宏（不依赖 Google Test 等外部框架）：

```cpp
#define TEST(name) printf("  TEST: %s ... ", name)
#define PASS()     do { printf("PASSED\n"); tests_passed++; } while(0)
#define FAIL(msg)  do { printf("FAILED: %s\n", msg); tests_failed++; } while(0)
#define ASSERT(cond, msg) if (!(cond)) { FAIL(msg); return; }
```

## 示例：Buffer 测试

### 测试1：基础读写

```cpp
static void test_basic_rw() {
    Buffer buf;
    ASSERT(buf.readable_size() == 0, "should be empty initially");  // 初始空

    buf.append("Hello, WeMeet!", 15);                                // 写入
    ASSERT(buf.readable_size() == 15, "size mismatch after append");

    std::string s = buf.retrieve_as_string(15);                      // 读出
    ASSERT(s == "Hello, WeMeet!", "data mismatch");
    ASSERT(buf.readable_size() == 0, "should be empty after retrieve"); // 读完后空
}
```

### 测试2：移动构造

```cpp
static void test_move_constructor() {
    Buffer buf1;
    buf1.append("move semantics test data", 24);
    size_t orig_size = buf1.readable_size();
    const uint8_t* orig_data = buf1.data();

    Buffer buf2(std::move(buf1));   // 移动构造

    ASSERT(buf1.readable_size() == 0, "moved-from buffer should be empty");  // 原对象变空
    ASSERT(buf2.readable_size() == orig_size, "moved-to buffer should have data");
    ASSERT(buf2.data() == orig_data, "data pointer should survive move");     // 指针没变
}
```

**这个测试验证了什么**：移动后 `buf1` 的数据被"偷走"给了 `buf2`，数据指针没变（零拷贝），`buf1` 变成空状态。

## 学习建议：从测试倒推源码

1. 打开 `test_buffer.cpp`，看看 `Buffer` 有哪些公开 API
2. 尝试自己写一个测试（比如"重复 append + retrieve 10 次后状态是否正确"）
3. 打开 `buffer.h`，对照测试理解每个 API 的实现
4. 如果测试失败了，恭喜——你发现了一个可以深入理解的点
