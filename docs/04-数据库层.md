## 1. ConnectionPool — RAII 连接池

**文件**：`connection_pool.h` + `connection_pool.cpp`

### 设计目的

`mysql_real_connect()` 涉及 TCP 三次握手 + MySQL 握手认证，开销巨大（几十~几百毫秒）。如果每次请求都建立新连接，性能极差。连接池预先创建一批连接并保持，业务代码**借→用→还**，复用 TCP 连接。

### 架构图

```
连接池 (ConnectionPool)
┌─────────────────────────────────┐
│  free_connections_  (空闲队列)   │
│  ┌───┐ ┌───┐ ┌───┐ ┌───┐     │
│  │ C1 │ │ C2 │ │ C3 │ │ C4 │  ← 4 个可用连接
│  └───┘ └───┘ └───┘ └───┘     │
└─────────────────────────────────┘
         │ borrow()      ▲ return()
         ▼               │
    ┌─────────┐    ┌──────────┐
    │ 线程A   │    │ 线程B    │
    │ conn→   │    │   ←conn  │
    │ query() │    │  query() │
    └─────────┘    └──────────┘
```

### C++ 技术点详解

#### 1.1 RAII 连接守卫

```cpp
class ConnGuard {
    MYSQL* conn_;
    ConnectionPool* pool_;
public:
    ConnGuard(MYSQL* conn, ConnectionPool* pool) : conn_(conn), pool_(pool) {}
    ~ConnGuard() { if (conn_) pool_->return_connection(conn_); }  // 析构自动归还
    MYSQL* get() { return conn_; }
};
```

**这是 RAII 的精髓**：业务代码拿到 `ConnGuard` 后只管用，用完离开作用域时析构函数自动归还连接。即使抛异常也不会泄漏。

#### 1.2 连接池设计要点

| 设计点 | 做法 | 原因 |
|--------|------|------|
| 初始连接数 | 4（最小） | 启动就创建，首次请求不用等 |
| 最大连接数 | 16 | 限制 MySQL 服务端压力 |
| 借连接 | 从空闲队头取，无空闲且未达上限则创建新连接 | 懒创建 |
| 还连接 | 放回空闲队列 | 复用 |
| 自动重连 | `MYSQL_OPT_RECONNECT` | 长连接断开后自动恢复 |

#### 1.3 条件变量等待

```cpp
MYSQL* acquire_connection() {
    std::unique_lock<std::mutex> lock(mutex_);
    // 等待直到有空闲连接或未达上限
    cv_.wait(lock, [this] {
        return !free_connections_.empty() || active_count_ < max_connections_;
    });
    // ... 取连接 ...
}
```

当所有连接都在使用时，请求线程阻塞在条件变量上，等待有连接归还后被唤醒。

## 2. UserRepository — 用户 CRUD

**文件**：`user_repository.h` + `user_repository.cpp`

### C++ 技术点详解

#### 2.1 Prepared Statement（预编译语句）

```cpp
// 一次性准备（编译 SQL）
MYSQL_STMT* stmt = mysql_stmt_init(conn);
mysql_stmt_prepare(stmt, "SELECT * FROM users WHERE email = ?", ...);

// 多次执行（绑定参数 → 执行 → 取结果）
mysql_stmt_bind_param(stmt, bind_params);  // 绑定 email
mysql_stmt_execute(stmt);                  // 执行
mysql_stmt_bind_result(stmt, bind_results); // 绑定输出列
mysql_stmt_fetch(stmt);                    // 取一行
```

**为什么用 Prepared Statement**：

1. **防 SQL 注入**：参数和 SQL 结构分开传递，恶意输入无法改变 SQL 语义
   ```
   // 不用 Prepared Statement → 危险!
   sprintf(sql, "SELECT * FROM users WHERE email = '%s'", user_input);
   // user_input = "' OR '1'='1" → 查出所有用户！

   // 用 Prepared Statement → 安全
   mysql_stmt_prepare(stmt, "SELECT * FROM users WHERE email = ?", ...);
   // user_input 被当作纯数据，不会影响 SQL 结构
   ```

2. **性能**：SQL 只编译一次，后续执行只需传参数，省去重复的 SQL 解析开销

#### 2.2 `std::optional` 返回值

```cpp
std::optional<User> find_by_email(const std::string& email);
```

**为什么用 optional**：语义清晰。调用方必须处理"没找到"的情况（`has_value()` / `value_or()`），编译器帮你避免忘记判空。

```cpp
auto user = user_repo_.find_by_email("xxx@test.com");
if (user.has_value()) {
    // 找到了，用 user->id
} else {
    // 用户不存在
}
```

#### 2.3 事务操作

添加好友是两步操作（A→B + B→A），如果第一步成功第二步失败，数据就不一致。事务保证原子性：

```cpp
mysql_query(conn, "START TRANSACTION");
// INSERT INTO friendships (user_id, friend_id) VALUES (1, 2);
// INSERT INTO friendships (user_id, friend_id) VALUES (2, 1);
mysql_query(conn, "COMMIT");   // 或 ROLLBACK 回滚
```
