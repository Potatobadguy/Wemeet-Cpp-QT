### 消息分发：策略模式的朴素实现

```cpp
void SignalingServer::on_message(const shared_ptr<TcpConnection>& conn, Buffer& buf) {
    BaseMessage base;
    Codec::decode_base_message(buf, base);    // 1. 解码外层信封

    switch (base.type()) {                     // 2. 根据 type 路由
    case MSG_LOGIN_REQ:       handle_login(conn, seq_id, buf);       break;
    case MSG_REGISTER_REQ:    handle_register(conn, seq_id, buf);    break;
    case MSG_HEARTBEAT_REQ:   handle_heartbeat(conn, seq_id, buf);   break;
    case MSG_MEETING_CREATE_REQ: handle_create_meeting(...);          break;
    case MSG_MEETING_JOIN_REQ:   handle_join_meeting(...);            break;
    case MSG_SDP_OFFER:       handle_sdp_offer(...);                 break;
    case MSG_CHAT_SEND:       handle_chat(...);                      break;
    // ...
    }
}
```

**处理流程**：收到消息 → 解外层 `BaseMessage` → 根据 `type` 找 handler → 解内层具体消息 → 调业务服务 → 编码响应 → 发送

### 登录处理的完整流程

```cpp
void SignalingServer::handle_login(conn, seq_id, buf) {
    // 1. 解码请求
    BaseMessage base;  LoginReq req;
    Codec::decode_base_message(buf, base);
    Codec::decode_payload(base, req);

    // 2. 调认证服务
    auto result = auth_service_->login(req.email(), req.password(), conn->conn_id());

    // 3. 构造响应
    LoginResp resp;
    resp.set_success(result.success);
    resp.set_token(result.token);
    resp.set_nickname(result.nickname);

    // 4. 编码并发送
    auto resp_buf = Codec::encode_wrapped(MSG_LOGIN_RESP, seq_id, resp);
    conn->send(std::move(resp_buf));   // 移动语义，零拷贝
}
```

**这个流程是本项目的核心模式**，所有消息处理都遵循：**解码 → 处理 → 编码 → 发送**，非常清晰。

## 2. AuthService — 认证服务

**文件**：`auth_service.h`（62行）+ `auth_service.cpp`（148行）

### 密码安全：SHA256 哈希

```cpp
std::string AuthService::hash_password(const std::string& password) {
    unsigned char hash[SHA256_DIGEST_LENGTH];
    SHA256((const unsigned char*)password.c_str(), password.size(), hash);
    // 转十六进制字符串
    std::ostringstream oss;
    for (int i = 0; i < SHA256_DIGEST_LENGTH; ++i)
        oss << std::hex << std::setw(2) << std::setfill('0') << (int)hash[i];
    return oss.str();
}
```

**绝不存明文密码**。数据库里存的 `password_hash` 是 `SHA256("123456")` 的结果（64 位十六进制字符串）。即使数据库泄露，攻击者也无法反推出原始密码（SHA256 是单向函数）。

> 生产环境建议加盐（salt）：`SHA256(password + random_salt)`，防止彩虹表攻击。

### Token 认证机制

```cpp
std::string AuthService::generate_token(uint64_t user_id) {
    // token = hex(user_id)_random1_random2
    std::ostringstream oss;
    oss << std::hex << user_id << "_" << random1 << "_" << random2;
    return oss.str();
}
```

**为什么需要 Token**：登录后客户端拿到 token，后续请求携带 token 而非密码：
- 密码只在登录时传一次，减少暴露风险
- token 有过期机制，即使泄露影响也有限
- token 里编码了 user_id，服务端无需查数据库就能识别用户

### 登录逻辑

```cpp
LoginResult AuthService::login(email, password, conn_id) {
    auto user = user_repo_.find_by_email(email);       // 1. 查用户
    if (!user) return {error: "User not found"};

    if (hash_password(password) != user->password_hash) // 2. 验证密码
        return {error: "Wrong password"};

    string token = generate_token(user->id);            // 3. 生成 Token

    user_mgr_->add_session({user->id, nickname, token, conn_id, ...}); // 4. 记录会话
    user_repo_.update_status(user->id, 1);              // 5. 标记在线

    return {success: true, user_id, token, nickname};   // 6. 返回结果
}
```

## 4. UserManager — 用户管理（16分片读写锁）

**文件**：`user_manager.h` + `user_manager.cpp`

### 分片读写锁设计

```
┌──────────────────────────────────────┐
│  UserManager                         │
│                                      │
│  shards_[0] → shared_mutex + map    │ ← user_id % 16 == 0
│  shards_[1] → shared_mutex + map    │ ← user_id % 16 == 1
│  ...                                 │
│  shards_[15] → shared_mutex + map   │ ← user_id % 16 == 15
└──────────────────────────────────────┘
```

### `shared_mutex` 读写锁

| 操作 | 锁类型 | 并发度 |
|------|--------|--------|
| 读（查用户状态） | `shared_lock` | 多个线程可同时读同一分片 |
| 写（登录/登出） | `unique_lock` | 写时独占，等待所有读完成 |

**为什么读写分离**：登录后的大部分操作是查用户在线状态（读），只有登入/登出才是写。`shared_mutex` 允许多个线程同时读，只有写时才独占。

### 分片策略

```cpp
size_t shard_idx = user_id % kShardCount;   // kShardCount = 16
```

不同 user_id 落到不同分片，不同分片的锁互不影响。如果只有一把大锁，1000 个并发请求只能串行；16 分片理论并发度提升 16 倍。
