## 1. Socket — RAII Socket 封装

**文件**：`socket.h`（168行，纯头文件实现）

### 设计目的

Linux 的 socket 是一个整数文件描述符（fd），忘记 `close()` 会泄漏。Socket 类用 RAII 保证 fd 一定被关闭。

### C++ 技术点详解

#### 1.1 RAII 生命周期

```cpp
~Socket() { close(); }           // 析构自动关闭

Socket(Socket&& other) noexcept  // 移动：偷走fd，原对象置空
    : fd_(other.fd_) {
    other.fd_ = kInvalidFd;      // 原对象变成 kInvalidFd，析构时不会 close
}

Socket(const Socket&) = delete;  // 禁止拷贝：两个对象不能拥有同一个 fd
```

**为什么禁止拷贝**：如果拷贝允许，两个 Socket 对象持有同一个 fd，析构时一个 close 后另一个尝试 close 已关闭的 fd，可能导致错误甚至关闭其他不相关的 fd。

#### 1.2 非阻塞 I/O 设置

```cpp
void set_nonblocking(bool on) {
    int flags = fcntl(fd_, F_GETFL, 0);
    if (on) flags |= O_NONBLOCK;
    else    flags &= ~O_NONBLOCK;
    fcntl(fd_, F_SETFL, flags);
}
```

**为什么需要非阻塞**：epoll 配合非阻塞 I/O 是 Reactor 模型的基础。如果 socket 是阻塞的，一个慢客户端就能卡住整个线程。

#### 1.3 TCP 选项优化

| 选项 | 作用 |
|------|------|
| `SO_REUSEADDR` | 服务器重启后可立即绑定同一端口（否则要等 TIME_WAIT） |
| `SO_REUSEPORT` | 多个进程可绑定同一端口（内核做负载均衡） |
| `TCP_NODELAY` | 禁用 Nagle 算法，小包立即发送（降低延迟） |
| `SO_KEEPALIVE` | TCP 层面心跳检测，发现死连接 |

#### 1.4 `SOCK_CLOEXEC` — fork 安全

```cpp
int fd = ::socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK | SOCK_CLOEXEC, 0);
```

`SOCK_CLOEXEC` 保证子进程 `exec()` 后不会继承父进程的 socket fd，防止 fd 泄漏到不该去的地方。

## 2. EventLoop — epoll 事件循环

**文件**：`event_loop.h`（110行）+ `event_loop.cpp`（239行）

### Reactor 模型核心

```
┌─────────────────────────────────────────┐
│              EventLoop                   │
│                                          │
│   while(running) {                       │
│     epoll_wait(...)    ← 阻塞等待事件    │
│        │                                 │
│        ├─ fd=3 → readable? → 回调()     │
│        ├─ fd=7 → readable? → 回调()     │
│        ├─ wakeup_fd → 处理待投递任务     │
│        └─ timer_fd → 执行定时器回调      │
│   }                                      │
└─────────────────────────────────────────┘
```

### C++ 技术点详解

#### 2.1 epoll 边缘触发（ET）

```cpp
void EventLoop::add_read_event(int fd, ReadCallback) {
    update_channel(fd, EPOLLIN | EPOLLET);   // ET = Edge Triggered
}
```

| 触发模式 | 行为 | 优点 | 缺点 |
|----------|------|------|------|
| **LT（水平触发）** | 只要缓冲区有数据就反复通知 | 编程简单 | 可能重复通知，浪费 CPU |
| **ET（边缘触发）** | 只在"无数据→有数据"变化时通知一次 | 高效 | 必须读干净，否则永远丢数据 |

**ET 模式下的正确读法**：必须循环 `read()` 直到返回 `EAGAIN`（表示读空了）。

#### 2.2 eventfd 唤醒机制

```cpp
// 构造函数中创建 eventfd
wakeup_fd_ = ::eventfd(0, EFD_NONBLOCK | EFD_CLOEXEC);

// 唤醒 epoll_wait
void EventLoop::wakeup() {
    uint64_t val = 1;
    ::write(wakeup_fd_, &val, sizeof(val));   // 写入 → epoll_wait 立即返回
}

// 消费 eventfd
uint64_t val;
::read(wakeup_fd_, &val, sizeof(val));        // 读出 → 清空状态
```

**为什么需要 wakeup**：其他线程想在本 EventLoop 中执行任务时，主线程正阻塞在 `epoll_wait`。通过向 eventfd 写入数据，epoll_wait 立即返回，主线程处理完投递的任务后继续循环。

#### 2.3 timerfd 定时器

```cpp
int EventLoop::run_every(int64_t interval_ms, TimerCallback cb) {
    int timer_fd = ::timerfd_create(CLOCK_MONOTONIC, TFD_NONBLOCK | TFD_CLOEXEC);

    struct itimerspec its{};
    its.it_value.tv_sec     = interval_ms / 1000;           // 首次触发时间
    its.it_interval.tv_sec  = interval_ms / 1000;           // 重复间隔
    ::timerfd_settime(timer_fd, 0, &its, nullptr);

    // 注册到 epoll，时间到 → timer_fd 可读 → epoll_wait 返回
    update_channel(timer_fd, EPOLLIN | EPOLLET);
}
```

**为什么用 timerfd 而不是 sleep 或闹钟信号**：timerfd 是文件描述符，可以直接加入 epoll，统一在事件循环中处理。不需要额外的线程或信号处理，代码更简洁。

#### 2.4 `epoll_ctl` MOD vs ADD

```cpp
void EventLoop::update_channel(int fd, uint32_t events) {
    epoll_event ev{};
    ev.events = events;
    ev.data.fd = fd;
    if (::epoll_ctl(epoll_fd_, EPOLL_CTL_MOD, fd, &ev) < 0) {
        if (errno == ENOENT) {
            ::epoll_ctl(epoll_fd_, EPOLL_CTL_ADD, fd, &ev);  // MOD 失败 → 说明是首次，改 ADD
        }
    }
}
```

先尝试 MOD（修改已有），失败则 ADD（首次添加）。避免维护"是否已注册"的状态。

#### 2.5 跨线程任务投递

```cpp
void EventLoop::run_in_loop(std::function<void()> task) {
    {
        std::lock_guard<std::mutex> lock(pending_mutex_);
        pending_tasks_.push_back(std::move(task));
    }
    wakeup();   // 唤醒 epoll_wait → 主线程处理新任务
}
```

允许其他线程安全地向本 EventLoop 提交任务。临界区极小（只操作 vector），wakeup 在锁外。

## 3. TcpConnection — TCP 连接管理

**文件**：`tcp_connection.h`（82行）+ `tcp_connection.cpp`

### C++ 技术点详解

#### 3.1 shared_ptr + enable_shared_from_this

```cpp
class TcpConnection : public std::enable_shared_from_this<TcpConnection> {
    // ...
};

// 使用示例：
auto conn = std::make_shared<TcpConnection>(io_loop, std::move(conn_sock), conn_id);
conn->start();

// 在回调中安全获取自己的 shared_ptr
void TcpConnection::handle_read() {
    auto self = shared_from_this();   // 防止回调执行期间对象被销毁
    // ... 处理读事件 ...
}
```

**为什么用 shared_ptr**：一个 TCP 连接可能被多处持有——EventLoop 在等它的事件、TcpServer 在记录它、业务层可能也在引用。最后一个持有者销毁时，连接自动关闭。

**为什么用 enable_shared_from_this**：`shared_from_this()` 让你在成员函数内部安全地获取自身的 `shared_ptr`。如果不继承这个，你只能 `shared_ptr<TcpConnection>(this)`，这会创建一个新的引用计数（导致双重释放）。

#### 3.2 std::any 上下文存储

```cpp
std::any context_;    // 类型安全的 void*

void set_context(std::any ctx) { context_ = std::move(ctx); }
template<typename T> T* get_context() { return std::any_cast<T>(&context_); }

// 使用：
conn->set_context(user_id);           // 存储 uint64_t
uint64_t* id = conn->get_context<uint64_t>();  // 取出
```

`std::any`（C++17）是类型安全的万能容器。存储任何类型，取出时指定类型，类型不匹配抛异常。比 `void*` 安全，不需要手动管理生命周期。

#### 3.3 移动语义发送

```cpp
void TcpConnection::send(Buffer&& buf) {
    // 零拷贝：直接将 buf 的所有权移动到发送队列
}
```

发送大 Buffer 时用 `&&` 移动，避免拷贝整个缓冲区。

## 4. EventLoopPool — One Loop Per Thread

**文件**：`event_loop_pool.h`（48行）+ `event_loop_pool.cpp`（56行）

### 主从 Reactor 架构

```
          client1  client2  client3  client4  client5
              \     /          \     /      \     /
               \   /            \   /        \   /
          ┌─────────────────────────────────────────┐
          │  主 Reactor (main_loop_)                │
          │  只负责 accept() 新连接                  │
          │  不处理 I/O                              │
          └────────────────┬────────────────────────┘
                           │ 轮询分发新连接
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ Worker 0 │ │ Worker 1 │ │ Worker 2 │  ... (16个)
        │ epoll     │ │ epoll     │ │ epoll     │
        │ client1   │ │ client2   │ │ client3   │
        │ client4   │ │ client5   │ │ ...       │
        └──────────┘ └──────────┘ └──────────┘
```

**为什么需要主从分离**：
- accept 开销很小（只是建立连接）
- 真正消耗 CPU 的是后续的 I/O 读写和业务处理
- 主 Reactor 一个线程负责 accept，不受 I/O 影响
- 多个 Worker Reactor 并行处理 I/O，充分利用多核 CPU

#### 4.1 轮询分发

```cpp
EventLoop* EventLoopPool::next_loop() {
    size_t idx = next_index_.fetch_add(1, memory_order_relaxed) % loops_.size();
    return loops_[idx].get();
}
```

每次 `fetch_add(1)` → 索引递增 → 取模 → 均匀分配到每个 Worker。

## 5. TcpServer — Reactor TCP 服务器

**文件**：`tcp_server.h`（70行）+ `tcp_server.cpp`（111行）

### 分片锁连接表

```cpp
static constexpr size_t kShardCount = 16;
struct Shard {
    std::mutex mutex;
    std::map<uint64_t, std::shared_ptr<TcpConnection>> connections;
};
std::array<Shard, kShardCount> shards_;
```

**为什么分片**：如果所有连接放在一个 map 里用一个 mutex 保护，高并发下所有操作串行化。分成 16 片后，不同分片可以并发操作（`conn_id % 16` 决定分片），并发度提升 16 倍。

#### 连接管理流程

```
handle_accept():
  1. listen_sock_.accept() → 拿到新连接的 fd
  2. conn_id = next_conn_id_++ (原子操作)
  3. pool_->next_loop() → 选一个 Worker EventLoop
  4. make_shared<TcpConnection>(worker_loop, sock, conn_id) → 创建连接
  5. 设置消息回调 → 设置关闭回调（从连接表中移除自己）
  6. shards_[conn_id % 16].connections[conn_id] = conn → 注册
  7. conn->start() → 开始监听事件
```
