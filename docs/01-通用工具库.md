## 1. Buffer — 高效字节缓冲区

**文件**：`buffer.h`（160行，纯头文件实现）

### 设计目的

音视频帧动辄 MB 级别，频繁拷贝会导致严重性能问题。Buffer 通过**移动语义**实现零拷贝传递，通过**双索引**实现无搬移的流式读写。

### 核心数据结构

```
buffer_: [xxxxxxxx|**********data********|_____free_____]
         ←─ 8B ─→ ←── readable_size ──→ ←─ writable ──→
         prepend    read_idx_            write_idx_
```

- `read_idx_`：已读位置，调用 `retrieve()` 前移
- `write_idx_`：已写位置，调用 `append()` 后移
- 前 8 字节（`kPrependSize`）：为协议长度头预留

### C++ 技术点详解

#### 1.1 移动构造 `Buffer(Buffer&&)`

```cpp
Buffer(Buffer&& other) noexcept
    : buffer_(std::move(other.buffer_)),    // 偷走内部 vector
      read_idx_(other.read_idx_),
      write_idx_(other.write_idx_) {
    other.read_idx_ = kPrependSize;          // 原对象变成空状态
    other.write_idx_ = kPrependSize;
}
```

**为什么用 `&&`（右值引用）**：`Buffer&&` 表示"即将销毁的临时对象"。移动构造直接把内部数据指针偷过来（O(1)），而不是逐个字节拷贝（O(n)）。写 `noexcept` 是因为不抛异常，允许 STL 容器优化。

**适用场景**：任何需要传递大对象的场景——网络帧传递、文件读取、图像处理。

#### 1.2 禁止拷贝 `= delete`

```cpp
Buffer(const Buffer&) = delete;
Buffer& operator=(const Buffer&) = delete;
```

音视频帧不应被意外复制。编译器会在你尝试拷贝时报错，强制使用移动语义或引用传递。

#### 1.3 空间回收 `ensure_writable()`

```cpp
void ensure_writable(size_t len) {
    if (writable_size() >= len) return;                          // 够写，直接返回
    if (writable_size() + prependable_size() >= len + kPrependSize) {
        // 已读空间 + 剩余空间够 → memmove 回收
        memmove(buffer_.data() + kPrependSize, buffer_.data() + read_idx_, readable);
    } else {
        buffer_.resize(write_idx_ + len);                        // 不够 → 扩容
    }
}
```

三段式逻辑，避免频繁 `memmove`。只有当剩余空间不足且回收已读空间后仍不够时才扩容。

#### 1.4 右值引用限定成员函数 `to_string() &&`

```cpp
std::string to_string() && {   // 只能在右值上调用
    return retrieve_as_string(readable_size());
}
```

`&&` 放在函数后面表示"只能在右值对象上调用"。调用后 Buffer 被清空，所有权转移到 string。编译期间防止在左值上误调用。

## 2. MemoryPool — 三级线程本地内存池

**文件**：`memory_pool.h`（92行）+ `memory_pool.cpp`（75行）

### 设计目的

频繁调用 `new`/`delete`（底层是 `malloc`/`free`）会陷入内核态，在高并发服务器中是性能瓶颈。内存池预先分配大块内存，后续分配释放只是链表操作，极大减少系统调用。

### 架构图

```
线程A                    线程B                     线程C
  │                        │                        │
  ▼                        ▼                        ▼
ThreadLocalPool         ThreadLocalPool          ThreadLocalPool
  ├─ free_lists[SMALL]    ├─ free_lists[SMALL]     ├─ free_lists[SMALL]
  ├─ free_lists[MEDIUM]   ├─ free_lists[MEDIUM]    ├─ free_lists[MEDIUM]
  └─ free_lists[LARGE]    └─ free_lists[LARGE]     └─ free_lists[LARGE]
        ↕                        ↕                       ↕
   malloc/free              malloc/free             malloc/free
  (仅首次/溢出时)          (仅首次/溢出时)          (仅首次/溢出时)
```

每线程独立，零锁竞争。

### C++ 技术点详解

#### 2.1 三级分档

| 档次 | 大小 | 用途 |
|------|------|------|
| SMALL | 8 KB | 网络包头、小消息 |
| MEDIUM | 64 KB | 业务消息体 |
| LARGE | 1 MB | 媒体元数据、大帧 |

**为什么分档**：不同大小的请求走不同档次，避免小块占大槽浪费内存（内部碎片）。

#### 2.2 `thread_local` — 线程局部存储

```cpp
static thread_local ThreadLocalPool tls_pool_;
```

`thread_local` 关键字让每个线程拥有自己独立的 `ThreadLocalPool` 实例。线程A分配不会碰到线程B的池，**天然零锁竞争**。

**适用场景**：任何需要高频分配且线程间不需要共享的内存的场景——连接池中的缓冲区、日志缓冲区、请求上下文。

#### 2.3 `std::aligned_alloc(64, ...)` — 缓存行对齐

```cpp
return std::aligned_alloc(64, block_size);
```

64 字节对齐让分配的内存起始地址是 64 的倍数，正好占满一个 CPU 缓存行。对 SIMD 指令和频繁访问的数据有显著性能提升。

#### 2.4 溢出控制

```cpp
if (freelist.size() < kMaxBlocksPerTier) {
    freelist.push_back(ptr);       // 归还池
} else {
    std::free(ptr);                 // 归还系统
}
```

每个 Tier 最多保留 64 个块（`kMaxBlocksPerTier = 64`），防止内存池无限膨胀。

#### 2.5 RAII 析构清理

```cpp
ThreadLocalPool::~ThreadLocalPool() {
    for (size_t t = 0; t < static_cast<size_t>(Tier::COUNT); ++t) {
        for (void* ptr : free_lists[t]) {
            std::free(ptr);          // 线程退出时自动归还所有系统内存
        }
    }
}
```

线程退出时 `thread_local` 变量自动析构，`free` 所有池中内存，无泄漏。

## 3. LockFreeQueue — 无锁 SPSC 环形队列

**文件**：`lockfree_queue.h`（108行，纯头文件实现）

### 设计目的

在音视频采集线程 → 编码线程的场景中，如果用 `std::mutex` 保护队列，锁竞争会导致 CPU 空转。SPSC 无锁队列用纯 `std::atomic` + CAS 实现，零阻塞、零系统调用。

### C++ 技术点详解

#### 3.1 CAS（Compare-And-Swap）实现

```cpp
bool try_push(const T& item) {
    size_t write = write_pos_.load(memory_order_relaxed);
    size_t next  = write + 1;
    if (next - read_pos_.load(memory_order_acquire) >= capacity_)
        return false;                       // 队列满
    buffer_[write & mask_] = item;
    write_pos_.store(next, memory_order_release);  // 发布写入
    return true;
}
```

**为什么不需要锁**：SPSC = 单生产者单消费者。只有一个线程写 `write_pos_`，只有一个线程读 `read_pos_`，不存在写-写竞争，只需要保证读-写之间的可见性（内存序）。

#### 3.2 内存序（Memory Order）

| 操作 | 内存序 | 含义 |
|------|--------|------|
| `read_pos_.load(acquire)` | acquire | 读端获取生产者写入的可见性 |
| `write_pos_.store(release)` | release | 写端确保数据对消费者可见 |
| `write_pos_.load(relaxed)` | relaxed | 仅读当前值，不需同步（本地线程独写） |

**为什么不用 `seq_cst`（默认最强）**：更严格的内存序需要额外的 CPU 内存屏障指令。`relaxed` 和 `acquire/release` 配合使用，在保证正确性的前提下达到最高性能。

#### 3.3 缓存行对齐消除伪共享

```cpp
alignas(64) std::atomic<size_t> write_pos_;  // 在缓存行0
alignas(64) std::atomic<size_t> read_pos_;   // 在缓存行1（不同行！）
```

**什么是伪共享（False Sharing）**：

```
没有 alignas(64):          有 alignas(64):
┌──────────────┐            ┌──────────────┐
│ write_pos_   │ ← 核心A写  │ write_pos_   │ ← 核心A写 (缓存行0)
│ read_pos_    │            ├──────────────┤
└──────────────┘            │    padding    │
  同一缓存行!               ├──────────────┤
  核心A写 → 核心B的缓存行失效  │ read_pos_    │ ← 核心B读 (缓存行1)
                            └──────────────┘
                              不同缓存行，互不影响!
```

当两个原子变量在同一缓存行时，核心A写 `write_pos_` 会导致核心B的整个缓存行失效，即使核心B只读 `read_pos_`。用 `alignas(64)` 把它们分开到不同的缓存行，彻底消除这个问题。

#### 3.4 容量取 2 的幂 + 位掩码

```cpp
capacity_ = next_power_of_two(capacity);
mask_ = capacity_ - 1;
// ...
buffer_[write & mask_] = item;   // 位运算取模，比 % 快
```

`x & (2^n - 1)` 等价于 `x % 2^n`，但位运算比取模运算快约 5-10 倍。

## 4. ThreadPool — 固定大小线程池

**文件**：`thread_pool.h`（87行）+ `thread_pool.cpp`（54行）

### 设计目的

避免频繁创建/销毁线程（代价高昂）。预先创建固定数量的工作线程，任务到达时分配给空闲线程执行。

### C++ 技术点详解

#### 4.1 条件变量实现生产者-消费者

```cpp
void worker_loop() {
    while (true) {
        std::function<void()> task;
        {
            std::unique_lock<std::mutex> lock(mutex_);
            cv_.wait(lock, [this] {
                return stop_ || !tasks_.empty();   // 有任务或要退出时唤醒
            });
            if (stop_ && tasks_.empty()) return;
            task = std::move(tasks_.front());        // 取任务
            tasks_.pop();
        }   // ← 锁在此释放，任务在锁外执行
        task();
    }
}
```

**为什么用 `condition_variable`**：如果不用条件变量，线程只能忙等（`while(tasks_.empty()) {}`），CPU 100%空转。条件变量让线程在无任务时**休眠**，有任务时被**唤醒**，CPU 接近 0%。

#### 4.2 `packaged_task` + `future` 实现异步返回值

```cpp
auto enqueue_with_result(F&& f, Args&&... args) -> std::future<result_type> {
    auto task = std::make_shared<std::packaged_task<result_type()>>(
        std::bind(std::forward<F>(f), std::forward<Args>(args)...));
    std::future<result_type> result = task->get_future();
    tasks_.emplace([task]() { (*task)(); });    // 包装成 void() 放入任务队列
    return result;                        // 调用者拿到 future，后续 .get() 获取结果
}
```

**为什么用 `shared_ptr` 包装 `packaged_task`**：`packaged_task` 不可拷贝，但 lambda 需要捕获可拷贝对象。用 `shared_ptr` 包装后，多个 lambda 可以共享同一个 task。

#### 4.3 优雅关闭

```cpp
~ThreadPool() {
    stop_ = true;
    cv_.notify_all();           // 唤醒所有等待的线程
    for (auto& w : workers_) {
        if (w.joinable()) w.join();  // 等待每个线程执行完当前任务
    }
}
```

先设标志位 → 唤醒所有线程 → `join` 等待退出。确保所有提交的任务都有机会执行完毕。

## 5. Logger — 异步双缓冲日志

**文件**：`logger.h`（82行）+ `logger.cpp`（149行）

### 设计目的

日志写入磁盘是慢操作（I/O），如果业务线程同步写日志，日志会成为性能瓶颈。双缓冲设计让业务线程只写内存（快），后台线程负责刷盘（慢），两者并行。

### 架构图

```
业务线程1 ─┐
业务线程2 ─┤  write ──→ [前台缓冲 buffer[0]] ──满了交换──→ [后台缓冲 buffer[1]]
业务线程N ─┘             ↑ 有锁保护                    ↑ 后台线程刷盘
                    current_buffer_                    flush_thread_
```

### C++ 技术点详解

#### 5.1 双缓冲交换

```cpp
if (buf.used + total >= kBufferSize) {
    cv_.wait(lock, []{ return !buffer_ready_; });  // 等待后台刷完
    current_buffer_ = 1 - current_buffer_;          // 交换缓冲区
    buffer_ready_ = true;
    cv_.notify_one();                               // 唤醒后台刷盘
}
```

两个缓冲区轮流使用：前台写满 → 等后台完成上一轮刷盘 → 交换指针 → 后台开始刷刚写满的缓冲区。

#### 5.2 `__FILE__` / `__LINE__` / `__func__` 宏

```cpp
#define LOG_INFO(fmt, ...) Logger::instance().log(LogLevel::INFO, \
    __FILE__, __LINE__, __func__, fmt, ##__VA_ARGS__)
```

这些预定义宏在编译时展开为当前文件名、行号、函数名，日志里就能精确知道哪行代码打的日志。

#### 5.3 变参 `vsnprintf`

```cpp
va_list args;
va_start(args, fmt);
vsnprintf(msg, sizeof(msg), fmt, args);   // C 风格格式化，比 iostream 快
va_end(args);
```

`va_list` 是 C 语言处理可变参数的机制。对于高频日志，C 风格格式化比 C++ 的 `std::ostringstream` 快很多。
